# 문학 대화 수업 프로토타입

현재 작업 중인 프로젝트다. `db/schema.sql`은 별도 시험 프로젝트에서 적용·검증한 초안이며 운영 데이터베이스에 적용하면 안 된다. 실제 학생 데이터 적용 전 학교의 권한·보관·음성 정책과 보안 검토가 필요하다. `npm test`는 독립 규칙과 모의 서비스 기반 흐름을 검사하며 실제 외부 연결을 검증하지 않는다.

2026-11-24 1차 수정은 진행 중이다. 실제 시험 Supabase에서 가상 학생·교사, 루브릭, 10회 대화 저장, 요약 및 두 피드백과 일부 RLS를 시험했다. AI 응답은 모의 처리했으며 실제 모델·음성·수업 환경 전체는 검증하지 않았다. 공개 미리보기는 UI·연습 퀴즈만 제공하며 실제 대화나 저장 기능을 제공하지 않는다.

`npm install` 후 `npm run test:db`는 PGlite의 임시 PostgreSQL 호환 DB에 가상 Auth·Storage 구조와 가상 계정을 만들고 스키마, 학급별 RLS, 피드백 비공개, 제출 순서 및 음성 저장 정책을 확인한다. 실제 Supabase의 Auth·Storage 동작, 네트워크 API 및 동시성 검증을 대신하지 않는다.

기존 Supabase `literary_works`는 변경하지 않는다. 실제 키나 학생 정보는 소스, 예제 파일, 깃 저장소에 넣지 않는다.

현재 학생 인물과 자료 화면은 김초엽의 「관내분실」 시범 수업에 맞춰져 있다. 다른 작품에 잘못 적용되지 않도록 교사의 작품 선택과 학생의 과제 목록을 해당 작품으로 제한한다. 작품 DB 연결이 실패하면 수업 계정 화면을 열지 않는다.

공개된 과제와 교사가 확정한 루브릭은 평가 근거를 보존하기 위해 수정하지 않는다. 수업 자료나 루브릭을 바꾸려면 새 과제를 만든다. 학생은 공개된 과제의 교사 검토 설명을 화면에서 확인한다.

교사는 미확정 피드백을 `교사 초안 저장`으로 별도 보관하고 나중에 이어서 편집할 수 있다. 이 초안은 작성한 담당 교사에게만 보이도록 설계했으며 학생은 확정·공개된 피드백만 본다. 가상 계정으로 담당 교사가 AI 초안을 볼 수 있고 학생에게 두 종류의 초안이 보이지 않음을 시험했다.

로컬 화면: Node.js 24 이상에서 `npm start` 실행 후 `http://127.0.0.1:4173`에 접속한다. 실제 연결에는 `.env.example`을 `.env`로 복사하여 Supabase URL·공개 키와 서버 전용 Supabase 비밀 키·OpenAI API 키·사용 가능한 모델을 설정해야 한다. 서버는 기본적으로 로컬 주소에만 바인딩하며 `.env`는 Git에서 제외한다. 환경설정이 없으면 자료 화면만 표시된다.

설정 후 `npm run check:config`로 시험용 Supabase Auth와 OpenAI 모델 접근을 읽기 전용으로 확인한다. 키나 서버 응답 본문은 출력하지 않는다. 확인은 비밀 키·DB 권한·실제 대화가 정상이라는 뜻은 아니다.

## 기존 GitHub 화면과 배포

기존 공개 저장소의 `index.html`과 이 폴더의 Node 서버는 별도 구현이다. GitHub Pages는 정적 화면을 제공하므로 `server.mjs`의 API를 실행하거나 서버 비밀 키를 안전하게 보관하는 위치로 사용하지 않는다. 이 구현을 배포하려면 서버를 별도로 운영하고 HTTPS, 접근 제한, 환경 변수와 Supabase 허용 설정을 검증해야 한다. 서버의 기본 바인딩은 로컬 전용이며 원격 학생 접속용으로 배포된 상태가 아니다. 추후 공개 서버에서는 `HOST=0.0.0.0`, 제공된 `PORT`, 실제 웹 주소의 정확한 HTTPS 출처를 `ALLOWED_ORIGIN`으로 설정한다(예: `https://class.example.com`, 경로·끝의 슬래시 제외). 공개 바인딩에는 출처 설정이 필수이며 `Origin`이 있는 API 요청은 정확히 일치할 때만 허용한다. 이 검사는 인증이나 요청량 제한을 대신하지 않는다. 공개 저장소에는 `.env`, 실제 학생 기록, 음성, 교과서 원문을 올리지 않는다.

실제 수업에는 테스트용 Supabase 프로젝트에서 스키마와 RLS를 검증하고 학교가 발급한 Auth 사용자와 `ld_profiles`, `ld_classes`, `ld_memberships`를 관리자가 등록해야 한다. 교사가 루브릭을 확인해 과제를 공개한 후 학생이 접속한다. 음성은 학교의 보관·삭제·안내 절차가 확정된 뒤에만 별도 `db/voice-storage.sql`, `VOICE_STORAGE_APPROVED=true`, 보관·삭제 안내문 `VOICE_RETENTION_NOTICE`로 활성화한다. 실제 학생 사용이나 외부 배포 전에는 보안 검토와 전체 흐름 테스트가 필요하다.

음성 파일 업로드와 녹음 메타데이터 저장은 별도 요청이다. 메타데이터에는 저장소에 실제 존재하는 파일만 연결하도록 설계했다. 업로드 후 메타데이터 저장이 실패하면 연결되지 않은 파일이 남을 수 있으므로, 학교가 승인한 보관·삭제 절차에 해당 파일의 확인과 정리 방법을 포함해야 한다.

학교가 녹음 저장·고지·보관 정책을 승인해 기능을 켠 경우, 학생은 이용 체크 전에도 녹음 파일을 비공개 저장할 수 있다. 체크하지 않았거나 체크를 해제하면 학생과 교사의 파일 재생 및 외부 음성 인식은 차단되고 파일은 보관된다. 이용 상태 변경은 DB에 저장한다. 저장에 대한 안내와 학교 기준은 별도로 적용하며, 파일을 자동 삭제하지 않는다.

새 테스트 전용 프로젝트에 작품 테이블이 없으면 `db/test-work.sql`을 사용해 시험용 작품과 카드 3개를 준비할 수 있다. 이 파일은 기존 작품 테이블이 있으면 실패하도록 만들어져 있으며, 실제 작품 DB에는 실행하지 않는다. 시험용 작품 테이블을 만든 뒤에만 `db/schema.sql`을 적용한다. 현재 별도 시험 프로젝트에는 이미 적용했으며 가상 계정·학급으로 일부 권한을 시험했다. 같은 SQL을 다시 적용하기 전에 기존 테이블과 정책을 확인한다.

테스트 프로젝트에 스키마를 적용하고 Authentication에서 가상의 교사·학생 계정을 각각 만든 뒤, `db/setup-test-class.sql`에서 두 이메일 자리표시자만 교체해 실행하면 시험 학급과 소속을 준비할 수 있다. 이 파일에는 비밀번호나 실제 학생 정보를 넣지 않는다. 기존 역할이 다르면 변경하지 않고 오류가 나며, 같은 시험 학급·소속은 중복 생성하지 않는다. 운영 프로젝트에 실행하지 않는다.

`npm run prepare:sql-check`는 현재 스키마와 구조 확인문을 합쳐 `db/schema-validation.sql`을 만든다. **테스트 전용 Supabase 프로젝트**의 SQL Editor에서 전체를 실행하면 생성·권한·트리거 검사 뒤 롤백한다. 작품 테이블이 없는 빈 시험 프로젝트에서는 트랜잭션 안에 최소한의 임시 작품 테이블을 생성하며, 이 또한 롤백한다. 이 임시 테이블은 실제 앱의 작품 조회를 위한 테이블이 아니다. 실패하면 오류를 확인하고 트랜잭션이 종료됐는지 확인한다. 이 검사는 문법과 일부 구조 확인이며 학생·교사별 RLS, 동시성, Storage 권한 또는 실제 API의 검증을 대신하지 않는다.

AI 요청은 인증된 사용자별로 서버 프로세스당 1분에 60회로 제한하며 초과 시 저장한 발화·녹음을 유지하고 재시도를 안내한다. 이는 단일 프로세스 메모리 제한이므로 재시작하면 초기화되고 여러 서버 인스턴스에 걸친 총량이나 비용 상한은 보장하지 않는다. 공개 운영 전에는 호스팅의 공유 요청 제한과 OpenAI 사용량·예산 관리, 실제 동시 접속 시험을 별도로 구성한다.

## 실제 시험 결과와 다음 설정

별도의 `literary-dialogue-test` 프로젝트에 가상 계정과 시험 데이터가 있다. `tests/live-supabase-test.mjs`는 실행할 때마다 새 가상 계정과 기록을 만들며, 지정된 시험 프로젝트에서만 동작하고 OpenAI 응답은 가상 처리한다. 비밀번호·키는 출력하거나 파일에 저장하지 않는다. 이미 생성한 가상 데이터가 있으므로 필요할 때만 실행한다.

현재 시험 프로젝트의 작품·학습 테이블 API는 연결됐고, 가상 계정으로 교사 루브릭 확정부터 대화 10회, 초안 세 개, 1·2차 제출·교사 피드백 및 일부 타인 접근 차단을 확인했다. 실제 OpenAI 모델 확인은 HTTP 401이었으므로 `app/.env`의 `OPENAI_API_KEY`와 `OPENAI_MODEL`을 사용자가 직접 확인하고 저장한 뒤 `npm run check:config`를 다시 실행한다. 실제 키는 채팅이나 GitHub에 올리지 않는다. 실제 OpenAI 대화·평가, 앱 브라우저의 실제 연결, 음성 저장과 공개 서버의 전체 보안은 아직 검증하지 않았다.
